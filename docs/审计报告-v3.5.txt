选举地图志 / Election Atlas
现有版本审计与 v4 方向
============================================================
审计对象：election-atlas/dist（与 election-atlas.zip 内容一致）
渲染口径：Chrome 无头 1920×1080，四个视图实拍（audit/*.png）
          加 CSS/JS 静态统计
日期：2026-11-02

------------------------------------------------------------
0. 一句话结论
------------------------------------------------------------
不是"配色不够美"，是三个结构性缺失：没有设计系统、
信息层级倒置、没有编排与叙事。所以它读起来像
"一个能跑的 GIS 后台"，而不是"选举地图志"。

------------------------------------------------------------
1. 三个根因（可量化）
------------------------------------------------------------
1.1 没有设计系统
    字号声明：10px×32、9px×22、11px×19、8px×12、7px×2，
    全部 ≤11px 占绝对多数；另有一个 65px。没有模数比例。
    底色十几种肉眼无差的灰蓝：
      #f7f9fc #f9fbff #f5f8fb #f0f3f7 #eef2f8 #edf3ff
      #fbfcff #f9fbfd #f6f9fc #f4f7fc #f1f6ff #f1f4f8 #eff3f7
    灰字也有 4 种近色： #8c9bb0 #8b9eb6 #8b99aa #8392a5
    45 处 border-radius、20 处 box-shadow、3 处 backdrop-filter。
    字体只有 'Segoe UI','Microsoft JhengHei'：无 webfont、
    无数字字体、无 tabular 对齐。
    断点只有 max-height:800px 与 min-width:1500px。
    后果：必然"脏、飘、廉价"。7–10px 的中文在任何屏幕上
    都读不出；十几种灰蓝让面板边界糊成一片。

1.2 信息层级倒置
    全台数字出现 4 次：顶部 4 张 KPI 卡、右栏"全國概況"、
    左列表表头、页脚。
    地图面板占约 45% 视口，但岛体只画在面板左侧约 1/3
    宽度内，面板里约 3/4 是空白。
    屏幕上最大的字是 40.05%。
    后果：眼睛先看到重复数字，最后才找到地图。

1.3 没有编排
    animation 声明 0 条；transition 仅 10 条；
    innerHTML 全量重建 28 处；requestAnimationFrame 0 处。
    后果：每次切换都是"拆掉 DOM 再重建"，CSS transition
    对大多数元素不生效。"僵硬"的机械原因是架构，
    不是缓动曲线。

------------------------------------------------------------
2. 缺陷清单
------------------------------------------------------------

A. 地图（最致命）
  A1 分幅框是坏的。1.0× 下「連江縣」是空白矩形，
     「金門縣／澎湖縣」各只有 2–6px 色点。三个 130×130
     白框占掉面板左侧一整列却什么也没传达。
     改：独立投影 + 按内容 crop + 独立比例尺，
     并标注"比例不同"。
  A2 标签是死的。固定 7–9px，缩放时不重排、不避让
     （代码中无任何 collide 逻辑）。臺北市深链接 9.4×
     时 三芝/淡水/石門/金山/萬里 糊成一团，
     并与 大同/中山/松山 重叠。
     改：分级 LOD —— 国家级只留 22 县市名；≥4× 出乡镇名；
     8× 以上沿内切轴放置 + 避让 + 屏幕最小间距。
  A3 368 个乡镇边界在国家级全画 = 噪声，无简化、无 LOD。
     改：预生成三级 simplification 的 topojson。
  A4 没有选中态。臺北市深链接时地图上跟新北/基隆/宜兰
     毫无区别，只有左列表一行浅蓝底。
     改：选中上浮 + 外描边 + 邻居去饱和。
  A5 缺制图语言：无比例尺、无经纬网、无指北、
     无相邻地区名、无 hover 十字丝。
     右下角"1.0× / 滾輪縮放·拖曳平移"是操作说明，
     不是制图要素。
  A6 政党色与识别脱节：民進黨 #149c79（偏青的绿）、
     國民黨 #477bdb（长春花蓝）、民眾黨湖水绿。
     绿与湖水绿色相太近，368 个小色块分不清；
     三者都不是两党既有识别色。
     改：二选一 —— 用业界共识色（DPP 深绿 / KMT 靛蓝），
     或彻底走"数据色"（单色相明度编码差距）。不要混。
  A7 立委没有选区图。73 个选区只有列表和气泡，
     "地图"在这场选举里缺席。

B. 六视图（逐项见第 3 节）

C. 版面与排版
  C1 三栏各自滚动，1080p 下左栏与右栏都有滚动条，
     典型仪表盘病。
  C2 左栏一行 60px 只放两行 10px 文字，
     "百分點"被挤成竖排两字。
  C3 顶部 4 张 KPI 卡与右栏内容互为冗余；
     「有效票數 / 投票率」两个等宽方块把绝对值与比率
     并列，语义不等价。
  C4 右栏「前兩名差距」下一条彩虹渐变条（蓝→橙）配
     "0·接近 15 30+"，无单位、无指向、与政党色冲突，
     纯装饰。
  C5 满屏英文眉标：TAIWAN · EPSG:4326 / BEESWARM /
     WINNING MARGIN / EQUAL AREA / 22 UNITS / TERNARY /
     VOTE SHARE / SMALL MULTIPLES / SHARED SCALE /
     PARLIAMENT / REGIONAL SEATS。零信息量的装饰字。
  C6 页头挂着「2024 · 視覺原型」—— 把未完成的自我认知
     印在作品上。
  C7 表头「地區 / 得票最多」与行内「賴清德 · 38.13%」
     是两套信息组织叠在一列里。

D. 交互与状态
  D1 控件墙：顶部 4 + 6 个视图 tab + 5 个指标 pill +
     3 个层级/标签开关 = 18 个控件压在地图上方两行。
     用户不知道先点哪个。
  D2 深链接不同步（bug）：用 #r=63000/000 打开，
     地图缩到臺北市、右栏进臺北市，但左栏标题仍是
     「縣市結果」、仍列 22 个县市。
     原因：list-title 取 state.county，而 hash 恢复
     没写它。刷新即错乱。
  D3 视图切换无过渡；无面包屑（只有「全臺」按钮）；
     无键盘导航。role= 0 处，仅 23 个 aria-label、
     3 个 aria-pressed，没有 aria-live；
     框选后合计变了，读屏不知道。
  D4 搜索框画了 "/" 提示但没绑快捷键
     （全项目 addEventListener 只有 2 处）。

E. 数据与可信度（最伤"严肃"）
  E1 源资料是 1994–2024 的完整档案（省長、直轄市長、
     縣市長、議員、鄉鎮市長、代表、總統、立委、公投、
     補選），每场都带 elctks.csv（投開票所/村里层级）。
     当前产品只用了 2 场 × 鄉鎮市區。
     数据能力是"村里级 × 30 年"，产品是"乡镇级 × 1 年"。
  E2 立委只做 73 席區域，缺不分區 34、原住民 6；
     顶部「36 席 / 36 席 / 1 席」与「49.32%」并列，
     读者会以为这就是立法院。
  E3 没有任何一句结论。严肃数据产品的铁律是每张图
     配一句"所以呢"，例如"臺北市 0.04pp、644 票，
     全台最接近；柯文哲在竹北 38.3% 是其最高得票率
     地区"。现在全靠用户自己算。
  E4 无资料版本/抓取日期；「投票率 71.86%」旁没有
     选举人数，读者无法验算；口径说明藏在抽屉里，
     页面上没有指针。

F. 工程
  F1 传输约 1.4MB：data.json 497KB + towns.json 655KB
     + d3.min.js 280KB；http.server 不压缩、无缓存头。
  F2 368 条 path + 368 个 label 常驻 DOM，每次状态变化
     重建整段；无 rAF、无 keyed join、无 canvas。
  F3 两套 CSS 叠补丁（style.css 21.6KB + refine.css
     5.7KB）—— 视觉是"追加"出来的，不是"设计"出来的。
  F4 无构建、无 lint、无测试（只有 verify-prototype.py
     一个数据校验）。

3. 六视图逐项判决
------------------------------------------------------------
地理
  见第 2 节 A。

等格圖
  22 个六边形散落在面板中央，占不到 40% 面积；
  格内 3 行 8–9px 文字；描边过粗；无序；
  "等面积"的意义（可比人口/席次）在图例之外没被利用。
  改：规则网格 + 固定地理位次；只放"县市名 + 领先者"
  两行（11–12px），得票率进 hover。

並列
  三张 180px 迷你图，色阶全落在浅端（20–50%），
  三图看起来一模一样；每张左侧还挂着
  "連江縣/金門縣/澎湖縣"三个空标签。
  改：差值色阶（相对全国平均）或统一 0–60% 发散色阶；
  每图配一句"该候选人的地理基础在哪"。

三方
  三角形只占面板 1/3；368 点挤成中央一小坨、
  直径 3px 完全重叠；轴刻度 9px 灰字；
  无密度、无等高线、无 2020 幽灵层。
  改：hexbin/等高线做密度；点按地区色；
  四角注释"三方均势区"；叠加上一届点位看位移。

分布（蜂群）
  三条水平条带 + 纵向抖动 = 噪点；面板下 1/4 空白；
  图例卡压在图上；只有一条 0–50pp 轴，
  无中位数/四分位，不标极端值（0.04）。
  改：真 beeswarm（半径避让）+ 分位线 +
  标注"最接近的 3 个地区"。

議席
  73 点排成扇形，中间一个 65px 的「73」；
  无过半线、无 113 席全貌、无席次变化。
  改：标准半圆 113 席（區域 73 + 不分區 34 +
  原住民 6）+ 57 过半线 + 可点每席。

4. v4 蓝图
------------------------------------------------------------
4.1 信息架构：单页三段
    ① 一屏"全国态势"（地图为主 + 一条结果带）
    ② 下钻（县市→乡镇，地图就地缩放，列表变浮层）
    ③ 对比（两届/两人/两地，中间差值图）
    URL 承载全部状态。
4.2 版面：地图 ≥65% 宽、贴满视口高、不要卡片边框；
    列表压成 56px 结果条（名称 + 领先者 + 差距条），
    与地图双向高亮；详情改 320px 可折叠浮层。
4.3 设计系统：明体（Noto Serif TC）做标题与地名，
    黑体做 UI，数字 tabular-nums；8pt 栅格；
    字号阶梯 11/12/14/18/28/44；颜色只剩
    纸色/墨色/政党色 + 1 个强调色；
    圆角归零或统一 2px（45 种圆角是廉价感的重要来源）。
4.4 地图规范：三级 LOD、标签分级避让、选中上浮、
    固定读数条（不是浮动 tooltip）、比例尺 + 经纬网、
    分幅独立投影。
4.5 动效只动 4 处：flyTo（400ms）、fill crossfade
    （250ms）、列表 FLIP（200ms）、View Transitions；
    尊重 prefers-reduced-motion。
    不要数字滚动计数（装饰，不是信息）。
4.6 技术：Vite + 预生成 topojson（LOD0/1/2）+
    每场选举一个 JSON（按县市 lazy load）+
    D3 keyed join + canvas 底图 / SVG 交互层。
4.7 数据杀手锏：立委补到 113 席；再引入
    村里/投開票所层级（源数据支持）——同一张图从
    368 个乡镇放大到 7000+ 村里。

7. 三条不可退让的约束
------------------------------------------------------------
7.1 一屏只允许一条滚动轴（现在有三条）。
    列表横向化，详情进浮层。
7.2 字号下限 11px，正文 14px（现在 89% 的声明在 7–11px）。
    这一条不改，其他视觉工作都是白做。
7.3 状态全部进 URL，且恢复时地图/列表/详情同时同步
    （现在是坏的：深链接只同步了一半）。
